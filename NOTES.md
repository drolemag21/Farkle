## How the code is organized
- Source: `farkle-table.html`. Classic rules, 2-4 players online. (It began next to Farkle Showdown, a separate single-player roguelite that lives outside this repo and shares no code.)
- Host-authoritative: the room creator's page (`S.M`) is the only writer. Players send intents (`act` → `hostIntent`: sync, start, again, sel, keep, roll, bank); the host answers with an event (`hostEmit`: GAME_STARTED, DICE_SET_ASIDE, DICE_KEPT, DICE_ROLLED, FARKLE, BANKED, TURN_PASSED, GAME_OVER, LOBBY, PLAYER_LEFT/BACK, HOST_CHANGED) plus the full snapshot. Clients only render snapshots (`applyHost`, which validates them with `cleanState`) and play effects for events (`playEvent`).
- Dice: the host picks values with `crypto` and a seed; `makeLaunch(seed)` gives launch positions/velocities, sent in `st.roll`. Every screen runs `simulate(L)` (fixed 120 Hz step, only + - * / sqrt, so identical everywhere) and plays it back; the tumble angle is tied to the path still to travel, so each die lands on its value. The felt is `W` 300 × `H` 340, taller than wide so the dice are big on a phone; throw strength is one constant, `THROW` (scales launch speed, spin and, more gently, height in `makeLaunch`). 1 was the original soft toss (dice settle mid-table, rarely touch a rail); it's now 2.2 at the owner's request: dice hit the far rail about 1.5 times each and rebound across the felt, settling in ~1.45 s median, 2.0 s worst over 2,000 seeds (cap `MAX_STEPS` is 6 s). Changing `W`, `H` or the launch numbers changes every roll, so players on an old and a new copy would see different dice: ship such changes as an "everyone reload" release.
- Table view and layout: the camera (`CAM`) sits high over the near rail looking down at about 75 degrees, and `BOUNDS` frames the felt plus a sliver of rail (the outer rails run off the sides). `resize` gives the canvas the screen height left under the score cards after the turn panel (`#turn`) and the footer, capped at the full-width size; when keeping the footer would leave the table under 320 px (iPhone SE size), the footer sits just below the fold instead. A ResizeObserver on the board, table, turn panel and footer plus window `resize` refit it. Score cards are one line (dot, name, score, a hairline progress bar); four across (480 px+) they stack. That media rule must come after the base `.chip` rule: before it, the base `align-items: center` won and long names pushed the card's contents past its edge. Card status shows only "Away" now: the glow marks the roller. The footer shows the latest action (`st.log`), or the final-round warning, plus Leave; the target is printed on the felt.
- Transports share one interface (`join/publish/sendIntent/setMe/leave`): `RoomNet` (Claude room; everything rides on presence because event topics need Contributor access; 4 KiB presence cap), `SupaNet` (Supabase Realtime Broadcast + Presence on public channels, supabase-js 2.118.0 loaded from jsDelivr on demand; only works when the file is hosted outside Claude, since Artifacts block outside connections), `TabsNet` (BroadcastChannel, for testing in two tabs). Settings → Network picks one; Automatic uses the room inside Claude and Supabase elsewhere. The menu never names Supabase: the options read Automatic / Claude room / Online / This device only (`supabase` is the value behind Online), and only the ones that can work in this place are kept (the room is removed outside Claude, Online inside it; removed rather than hidden because iOS Safari lists hidden options). The URL and key fields sit under a collapsed "Custom server" and only show in the raw file outside Claude, never in the GitHub Pages build. Player-facing text (status pill, errors, toasts) says "Online" or "server", not Supabase.
- Hosted copy: `node tools/build-site.js` writes `docs/index.html` (GitHub Pages, served from `/docs` on `main`) from `farkle-table.html` plus `site.config.json`. It adds the doctype/charset/viewport head and the `[hidden]` rule (several panels set `display: flex` and would ignore `hidden` without it), and sets `window.FARKLE_HOSTED = { url, key }`; `CFG` uses those when the player hasn't saved their own, so players never see Settings. Uses the Supabase **publishable** key (`sb_publishable_...`; legacy anon keys retire in 2027). Settings → Save rejects `sb_secret_` keys.
- Presence: a player missing for `GRACE` (3.5 s) is marked away and their turns are skipped (counted in `skips`). If the host goes missing, the first connected seat takes over (`hostCheck` → `becomeHost`); ties between two hosts go to the snapshot that is `ahead`. A reloaded tab rejoins its room and seat from sessionStorage (`fk.sess`, `fk.pid`), and a reloaded host restores `fk.host`.
- Sound (`SND`, all Web Audio synthesis, no files): browsers allow no sound before a gesture, so it starts on the first tap or key (the splash's "Tap to start" is that tap) (`unlockAudio`, listening to pointerdown, pointerup, touchend, click and keydown: on touch screens pointerdown is not a user gesture, so phones need the others). `unlock` sets `navigator.audioSession.type = "playback"` where supported so the iOS silent switch doesn't mute it, and resumes an "interrupted" context too. Lounge bus = jazz trio in F at 74 bpm (`PROG`, `scheduleBar`: FM Rhodes with tremolo, walking bass, brushes, ride, sparse vibes) + sparse room sounds (chip clacks, glass clinks, a distant slot jingle), queued 1.5 s ahead by `pump`. The old brown-noise crowd murmur was removed (owner: it sounded like wind and sat over the music). `syncSound` sets the lounge level: 1 outside play (start screen, lobby, game over); during play 0 (fades out) unless "Music during games" is on (`#gmusic` header button, shown only on the game screen, localStorage `fk.gmusic`), then 0.6. Table sounds: `roll(sim, delay)` plays a `whoosh` from release to the first felt landing, then the impacts the physics step records in `sim.hits` (felt thud, rail knock, die-on-die `clack`). No slide hiss: it was filtered noise like the whoosh and sounded like it coming back (owner removed it). Die-on-die hits before the first felt landing are skipped: the handful starts packed and grazes in the air, and those clicks read as a keep. `clack` is a dry unpitched noise hit, deliberately unlike the pitched `click` that `tray` uses, for the same reason (owner); `select`, `tray` (die set down in the tray), `bank` (chip stack + bell), `hot` (whoosh, thump, crackle, vibes run), `applause(big)` (16 synthesized pairs of hands in the hall reverb; on BANKED when the turn had hot dice (`M.th`, sent as `d.hot`) or banked 1,000+, longer when both; shaped over 3.2 s, 4.2 s when both, then the build-up plays at `APPLAUSE_RISE` 0.75 and the fade at `APPLAUSE_FALL` 0.5 of that, by the owner's ear: peak about 0.5 / 0.7 s, gone by about 1.8 / 2.3 s), `farkle` (thump, then the trio hits one dark chord on the table bus: D half-diminished on the Rhodes, low D on the bass, a choked cymbal; `rhodes` and `bassNote` take an optional bus for this, scaled by `FARKLE_BAND`. Owner picked it from mockups over a tape stop, a bass slide and a choked bell; it replaced a muted "sad trombone" horn, too corny, and a rake + mallet version, too flat), `turn` (two vibes notes, on TURN_PASSED / GAME_STARTED when it becomes your turn). Reverb: one shared convolver (`impulse`, 0.8 s tail, return 0.075; owner asked for less twice, it was 2.8 s at 0.3), fed by the lounge (0.35), table sounds (0.12) and applause (0.5). Mute button in the header, kept in localStorage (`fk.mute`). Levels checked with `SND.measure(part)` (offline render, 10 s window): music about -26 dBFS RMS; hot -38, farkle -37, sizzle -44, flare -44, applause -44, bank -44, turn -44.
- Dice shape (`drawDie`, `DIE_PATCHES`): each die is a rounded cube. Faces are flat squares inset by `RND` (0.2 of a half-size); the edges are quarter-cylinders cut into `EB` flat bands and the corners are small fans, all built once in die-local space and lit per piece by its own normal. The die is convex, so back pieces are drawn first and front pieces over them, and each piece is stroked in its own fill colour to hide antialiasing seams. Display only; the physics still treats dice as sharp cubes.
- Dice colours: `DICE_COLORS` (red, green (lime-leaning, to stand off the felt), blue, orange, purple, cyan, plus six Christmas ones marked `xmas`, see Holiday look). A colour may name its own `pip` colour (the renderer sets `PIP` with `BODY`); otherwise pips are ivory. Picked on the start screen and in the lobby (`renderDicePickers`, `setDiceColor`; in the lobby the one `#lobby-dice` picker moves into a row under my seat while open), kept in localStorage (`fk.dice`), sent in presence as `me.dc`, copied to `player.dc` by the host in the lobby. The renderer paints all dice in the current roller's colour (`BODY`, set per frame in `draw`). The lobby slot shows a small swatch.
- Leader crown: `renderGame` puts a crown (`crownEl`) on the card of a single outright leader (none at 0 or in a tie); it pops in only when the leader changes (`S.leader`).
- Names are capped at 12 characters (`NAME_MAX`): `maxlength` on the field, `enterRoom` refuses a longer name (e.g. one saved in `fk.name` before the cap) with a toast, and `cleanName` cuts names from other browsers to 12. A live count sits on the label line (`renderNameHint`; the field's tooltip says the limit). Measured at 375 px: about 12 typical characters fit beside " (you)"; wide letters fit fewer. Score cards are one line now (name beside the score): re-measure if you change their font sizes. On wide screens (4-column board, 480 px+) cards are narrower and names cut sooner.
- Turn flow (owner's design, from player feedback asking for a set-aside step): turn stage `ts` goes pre → rolled → kept → rolled → ... → banked (or farkle). After a roll the only button is a gold **Keep** (`#btn-roll` relabelled; sends `keep`): tapped dice stay tentative (`sel`, `s: 1`) until Keep, which scores them together (`hostKeep`, one keep per roll, so a triple can't be split into singles) and locks them (`s: 2`). After a keep: gold **Roll N** (or "Hot dice: roll 6") and **Bank** (`hostBank` only from `kept`, so the banked total is already final). The gold button is always the next step; with nothing picked, Keep is greyed out because the next step is tapping dice. Keys: 1-6 pick, R or K press the gold button, B banks.
- Keep glide: on DICE_KEPT the dice just kept lift off the felt and arc into the tray one after another (`glideToTray`, `S.glide`, poses `where: "glide"`, drawn above the near rail). `applyHost` takes the pre-snapshot `poses()` as the glide's start positions. The glide happens at Keep, so the next throw no longer waits for it (the `wait` path on DICE_ROLLED is left in place but is now 0). Timing: `GLIDE_MS` 380 per die, `GLIDE_STAGGER` 45, `GLIDE_GAP` 90.
- Hot dice flair (`hotFlair`): neon "Hot dice!" banner that sputters on, and the roller's chip glowing (`data-hot`, timed by `FX.until`). From the second hot dice of a turn on (`st.hn`, hot dice this turn, sent as `d.hn`), `#table-wrap` gets the scorched shake (`.scorch`, the one removed in e36a1f4).
- Dice on fire (`FIRE`, `fireHeat`, `drawFlames`, owner 2026-11-09): the first hot dice of a turn sets every die (felt, tray, gliding) alight as the throw starts (`FIRE.lit`); they burn while `st.th` and the turn is `rolled`/`kept`, flames 15% taller per extra hot dice. Flames are time-based puffs drawn **behind** each die so the pips stay readable, plus a warm glow on the felt and ember edges (`p.heat` in `drawDie`). A Farkle douses them (`douse`: fire out in `DOUSE_MS`, smoke puffs, `SND.sizzle`); a bank flares them gold for `FLARE_MS`, throws sparks and cools over `COOL_MS` (`bankFlare`, `SND.flare`), all inside the 1.4 s before the turn passes. Smoke and sparks live in `FIRE.parts` at world points and outlast the turn. Levels: sizzle and flare about -44 dBFS.
- Rules (owner, 2026-11-08): the home screen offers **Classic** or **Custom** in place of the old Classic/Speed modes (Speed is Custom at 5,000). Classic (`CLASSIC`): first to 10,000, `open` 500 (your first bank must be at least that in one turn; until then Bank shows "Need 500" and `hostBank` refuses), `pen` 1,000 (third Farkle in a row; the score stops at 0, the count resets). Custom picks each value from `RULE_OPTS`; 0 turns a rule off. State carries `rules` (cleaned by `cleanRules`; a snapshot without it reads as Classic) and `target`, and each player `on` (on the board) and `fk` (Farkles in a row, 0-2; only counted when `pen` is on; a bank resets it). `onBoard(st, p)` is true when `open` is off. The host's Custom values and last choice are saved per device in localStorage `fk.rules` / `fk.ruleset`. `fillRules` draws the rule rows of the lobby card, which also marks values that differ from Classic. Score cards show "Off board" instead of a score, and red dots for Farkles toward the penalty in a small tab on the card's top-left corner (`.chip-fk`, opposite the crown; owner picked it from mockups so it takes no width from the name). The board's 12 px row gap is what keeps the tab clear of the card above. The rules are fixed once the room is created.
- Phone layout (owner picked from mockups, 2026-11-09): both screens fit 375 × 667 without scrolling, and 320 px wide. Home: name with its count on the label line, dice beside a "Dice" label (above it under 360 px), compact rule cards, Create, Join, and a "How scoring works" link. Custom's pickers and the scoring help open as bottom sheets (`.sheet`, `openSheet` / `closeSheets`; tapping the Custom card, even when already chosen, opens its sheet; Escape or the backdrop closes). Lobby: code row with **Invite** (`navigator.share` with a `?room=1234` link outside Claude, code only inside Claude; copy fallback), seats as a list with empty seats folded into one row, rules folded to one line (`#rules-line`, opens the full card), and an action bar pinned to the bottom (`.lobby-bar`, sticky; `#app` is full height so it sits at the screen's foot) with Leave as an icon. Opening the page with `?room=1234` fills in the join code unless a session is being resumed.
- Splash and title scene (owner picked from mockups, 2026-11-10): on arrival a splash shows the title over the table seen from a circling camera (`#splash`, `#scene`, section 12b). It waits for a tap (or Enter/Space) instead of timing out, because that tap is the user gesture that lets the lounge music start; `enterHome` then flies the title into the top bar logo (a FLIP transform) while the home screen rises in. Invite links (`?room=`) and rejoins (`fk.sess`) skip it. The scene keeps running behind the home screen (frosted panels, `#scr-start .panel`) and stops on the lobby and game screens (`sceneLoop`). Throws use the real `makeLaunch`/`simulate`, alternate ends of the table (mirrored), and between throws the dice are scooped to the next launch spot so none pop in or out; during the splash they cycle the colours, at home they're the player's (`S.me.dc`). The table is drawn from any side here (`drawTableBody`, `drawSide`, `drawOuterSides`: a rail is drawn after the dice when the camera is beyond its inner edge, and the outer sides of the table go last of all, since nothing on the table can be in front of them), copying `buildCaches`' colours, so change both together. The felt nap is mapped onto the table plane in a 4×5 grid of patches (each with its own affine map, anchored at the table corner so they line up), so it turns with the table instead of sitting still on screen. `drawDie`, `drawShadow` and `planeXf` read the game's camera globals; `inView(SV, fn)` swaps the scene's camera, scale and canvas in for one frame and restores them. Display only: nothing here touches state or the game's physics.
- The host has no ready button: pressing Start counts as their ready (`hostIntent` start skips the host in the all-ready check; `renderLobby` leaves the host out of "waiting for").
- Test mode (Settings, below Connection): a switch that reveals test tools, saved per browser in localStorage `fk.test` (`TEST`). Only where `TEST_OK` (no `FARKLE_HOSTED`, so never in the GitHub Pages build); the host checks `TEST_OK` itself before honouring a test intent. Tools: **Christmas mode** forces the holiday look on (see Holiday look). **Force hot dice** sends `hot: true` with each roll intent, and `hostRoll(forceHot)` marks every die kept first, so all six come back as hot dice. Add new tools to `#test-opts` the same way.
- Local testing: see `CLAUDE.md` → Testing. `tests/serve.js` is a tiny static server; it wraps skeleton-less `.html` files in the same head the Artifact publisher adds, so the source behaves as it does on claude.ai.
- Holiday look (owner picked "Deck the table" from mockups, 2026-11-10, without the wreath; mockups: https://claude.ai/artifact/HjgCqNVZ6ZjfQGfjLoiYaH). `XMAS.on` is true from Dec 1 to Jan 6 by the device's own clock (`xmasSeason`), or now by Test mode → Christmas mode (`TEST.xmas`, test link only; players get no switch). Per device and cosmetic only: nothing goes over the network except a chosen dice colour. `applyHoliday` switches everything at once: `html.xmas` (Santa hat on the logo, CSS), the table cache key (garland on all four rails, bulbs on the far rail, a gold-ink holly sprig at the top of the felt ring and "Merry & bright" on the felt: `DECO`, `drawGarland`, `drawLights`, `drawHolly`, drawn in `buildCaches` and in the title scene's `drawSide`/`drawTableBody`, so change both together), the leader's crown becomes a Santa hat (`crownEl`), the dice picker gains a second row of six (`pickableDice`: candy cane, gingerbread, gold ornament, frost, holly (dark green, red pips), poinsettia (red, green pips)); turning the look off moves a player on a Christmas colour back to red. The splash's throws cycle only the Christmas colours while it's on (only the usual six otherwise); at home the dice stay the player's own. Every copy can draw the Christmas colours; an older copy shows them as red (`diceColor` fallback). Snow (`#snow`, `snow()`): a fixed canvas under `#app`, so it falls behind the panels and over the title scene but never over the game table; about 30 fps, 30-90 flakes by screen area, still with reduced motion. Sound: `SND.holiday(on)` swaps the lounge tune at the next bar for "Snowfall at the Table" (`waltzBar`, `WALTZ`, `MEL`: an original jazz waltz in Bb, 3/4 at 138 bpm; chorus 1 celesta melody, chorus 2 vibes solo; sleigh bells on 2 and 3) and the bank's house bell for sleigh bells and a celesta run. Celesta and bells go to their own `bells` bus that skips the lounge lowpass. Levels: waltz about -25 dBFS (`measure("waltz")`, trio -26), holiday bank -45 (normal -44).
